Every character has a **gallery** of pictures on their web portal profile. The player adds images,
puts them in order, and gives each one a caption, tags and, when it needs one, a content warning. One
image is the character's avatar and one can be the banner across the top of the profile.

This page covers what players do with a gallery, what staff can change, and how a game decides what
happens when someone reports an image. The examples were run on a SharpMUSH server, and the output
shown is what it printed.

## What players do

The profile's Gallery card shows the avatar and two more images. **View all** opens the gallery page,
at `/character/<name>/gallery`, with every image in the player's order. Clicking an image opens it
large, with its caption and tags under it.

Whoever may edit the character's biography may edit the gallery: the account that owns the character,
and staff who control it. In the large view they can:

- move the image earlier or later in the gallery;
- make it the avatar or the banner;
- edit its caption, tags and content warning;
- share it in the [image library](#the-image-library);
- delete it.

**Add image** under the Gallery card, and **Change avatar** and **Change banner** on the profile, each
offer two ways in: upload a new file, or choose one from the image library.

The portal takes PNG, JPEG, GIF and WebP files up to 10 MB. It reads the start of each file to check
what it is, so a file renamed to `.png` is refused.

## Content warnings

A content warning is a few words, such as `blood` or `spiders`. A warned image is covered by its
warning everywhere the portal shows it: on the profile, on the gallery page and in the large view. The
picture is not even downloaded until the viewer chooses **Show image**.

Because the avatar and the banner show without a click, a warned image is never either of them. Warning the current avatar moves the avatar to the
first image without a warning.

## Tags

Tags are short words or phrases, up to ten per image, such as `portrait`, `docks` or `night`. The
portal stores them in lower case. The gallery page shows one button per tag; choosing one keeps only
the images that carry it. Moving an image while a tag is chosen moves it past its neighbour among the
images shown.

## The image library

The image library holds the pictures a game has already stored, so a map on the wiki or a picture in
one gallery can be used again without uploading the same file twice. Anyone signed in to the portal
can choose from it:

- in the wiki editor, with the image button in the toolbar, which inserts the picture into the page;
- in **Add image**, **Change avatar** and **Change banner**, which add it to the gallery without making
  a copy.

The library has a search box that narrows it by file name. A gallery takes only PNG, JPEG, GIF and
WebP, so drawings in SVG appear only in the wiki editor.

### What is in it

A file uploaded in the wiki editor or on the staff **Image Library** page (`/admin/media`) is in the
library straight away.

A file uploaded to a gallery belongs to that gallery until the player shares it: **Edit details** has
**Share in the image library**. Until then nobody else finds it in the library, and deleting it from the
gallery deletes the file. Sharing cannot be undone, because a wiki page or another gallery may already
show the picture; once shared, deleting it from the gallery keeps the file, and the form says so.

An image with a content warning cannot be shared. The warning belongs to the gallery, and the library
would show the picture uncovered.

### Locks

A file can be locked to a permission, such as `wiki.admin` or one the game defined with
[`@permission`](/reference/sharpmush-help/permission-command/). Only holders of that permission find it in the
library; its uploader and anyone with `media.admin` always do, and see a lock beside its name.

Staff set a lock on the **Image Library** page: the lock button on a file opens **Library sharing**,
with **Lock to a permission**. Leaving the field empty takes the lock off. The **Library** column shows
`One gallery`, `Everyone` or `Locked:` and the permission.

<Aside type="caution">
A lock hides a file from the library, not from the pages that already show it. Its address still
serves the picture to anyone who has it.
</Aside>

## Limits

| What | Limit |
| --- | --- |
| Images in one gallery | `max_gallery_images`, 50 unless the game changes it |
| Caption | 300 characters |
| Content warning | 100 characters |
| Tags | 10 per image, 32 characters each |
| File | 10 MB; PNG, JPEG, GIF or WebP |

`max_gallery_images` is in the Players group of `@config`. Set it in `mush.cnf`
(`max_gallery_images 80`), or in the game:

```sharp
> @config/set max_gallery_images=80
Option set.
> think config(max_gallery_images)
80
```

## Moderation

A game can take more control of its galleries with five options in the Gallery group of `@config`,
also on the portal's configuration page at `/admin/config/gallery`. Each is off by default, which
leaves a gallery to its owner. Staff here are those who hold `media.admin`: moderators, royalty and
wizards unless the game changes the roles.

| Option | What it does |
| --- | --- |
| `gallery_consent_text` | Terms an uploader accepts before every upload. Empty asks for nothing. |
| `max_gallery_megabytes` | How many megabytes one character's images take together. `0` sets no limit. |
| `gallery_limit_skips_official` | Official art counts toward neither limit. |
| `gallery_portrait_approval` | A player's new portrait waits for staff. |
| `gallery_staff_only` | Only staff add, change or remove images. |

### Terms

With `gallery_consent_text` set, the portal shows the terms before every upload, and before an image
is picked from the library. The image keeps who accepted them, when, and the words they read. Staff
see that record under **Edit** in the image viewer; players do not. An upload sent without accepting,
or after the terms changed while the uploader read them, is refused.

```sharp
> @config/set gallery_consent_text=I made this picture, or its artist lets me use it here.
```

### Space

`max_gallery_megabytes` limits how much one character's images take, beside the count in
`max_gallery_images`. An upload past it is refused with what is used and what the file needs:

```
This gallery's images take 0.7 MB of its 1 MB, and this one needs 0.7 MB. Remove an image or add a smaller one.
```

**Official art** is a portrait staff approved, or an image staff marked with **Official art** in the
image viewer. With `gallery_limit_skips_official` on, it counts toward neither limit, so staff can
give a character a portrait without using up the player's room.

### Portrait approval

With `gallery_portrait_approval` on, a player's new avatar waits for staff, and the current one stays
until they approve it. The button in the image viewer reads **Ask to set as profile icon**, and the
image shows a waiting badge to its owner and to staff until someone decides. The owner can withdraw
the request. Only the latest request waits.

Staff decide at `/admin/portraits`, which sets each request beside the portrait it would replace, or
in the image viewer:

- **Approve** makes the image the portrait and marks it official art.
- **Decline** leaves the image in the gallery as an ordinary picture.
- **Clear portrait** removes the current portrait, and the profile shows the default until staff
  approve another.

While approval is on, no image becomes the avatar by being first, and removing the avatar leaves
none. Two events tell the game what happened: ``GALLERY`SUBMIT`` when a player asks, and
``GALLERY`PORTRAIT`` when staff decide (see the [event reference](/reference/sharpmush-help/sharpevents/)).

### Lock

With `gallery_staff_only` on, only staff add, change or remove images, on any character. Players
still view and report them, and a player who tries to change one is told:

```
Only staff change galleries in this game.
```

### Softcode

While any of these options is on, ``PROFILE`GALLERY`` carries the `wizard` attribute flag, so
softcode cannot forge a terms record or official art. While portraits wait for approval or galleries
are locked, so do `IMAGE`, ``IMAGE`BANNER`` and ``IMAGE`ALT``, so a player cannot set their portrait by
hand. The flags follow the options at the next change made in the portal.

## Reports

A visitor signed in to the portal can report an image they think breaks the game's rules. SharpMUSH
keeps no reports of its own. It hands each one to the game's [event
handler](/reference/sharpmush-help/sharpevents/), and the game decides what a report does.

![A visitor signed in to the portal chooses Report and writes a reason. The server checks that the event handler answers GALLERY`REPORT, with that attribute or a package's attribute under it, and runs them as the reporter. The jobs package's GALLERY`REPORT`JOBS files a job in the Staff bucket; a game can write its own instead. With neither, the portal shows no Report button.](../../../assets/guide/gallery-report-flow.svg)

The portal shows a **Report** button only while the event handler answers the event: it has a
``GALLERY`REPORT`` attribute, or a package has added one under it, such as ``GALLERY`REPORT`JOBS``.
The event handler runs the event's own attribute and then each one under it, so several packages can
answer one event. A game with neither takes no reports, and nobody is offered a button that does
nothing.

### With the jobs package

The bundled jobs package sets ``GALLERY`REPORT`JOBS`` when it is installed. Each report becomes a job in
the Staff bucket, filed by the reporter, with the image's address, its caption and the reason. Staff
answer it like any other job:

```sharp
> +job 2
...
Image: /api/wiki-assets/8016be6a9711472482bddf7f9cdafe92/rail.png

Caption: At the harbour rail

Reason: Not my character
```

To send reports to another bucket, change ``DATA`GALLERY`BUCKET`` on the package's Jobs object
(`#15` here; use your game's dbref):

```sharp
> &DATA`GALLERY`BUCKET #15=Feedback
Jobs/DATA`GALLERY`BUCKET - Set.
```

### Writing your own

A game without the jobs package, or one that wants something else, sets the attribute itself. The
event's named arguments are:

| Argument | What it holds |
| --- | --- |
| `%#` | The reporter's character |
| `%<objid>` | The character whose gallery holds the image |
| `%<asset>` | The stored file's id |
| `%<url>` | The image's address on the site |
| `%<reason>` | What the reporter wrote |
| `%<caption>` | The image's caption, empty when it has none |

This tells connected wizards about every report:

```sharp
> &GALLERY`REPORT #9=@wizwall/emit [name(%#)] reported an image of [name(%<objid>)]: %<reason> (%<url>)
```

<Aside type="caution">
`%<reason>` is the reporter's own text. Use it as text, as above, and never pass it to `s()` or
`objeval()`: brackets in a reason stay as they were typed.
</Aside>

## New images

The ``GALLERY`ADD`` event runs after an image is uploaded. `%#` is the character who uploaded it,
`%<objid>` the character whose gallery it is, `%<asset>` and `%<url>` the stored file, and `%<use>`
one of `gallery`, `avatar` or `banner`: what it was uploaded as.

This tells connected wizards about every new picture:

```sharp
> &GALLERY`ADD #9=@wizwall/emit New picture for [name(%<objid>)]: %<url> as %<use>
Event Handler/GALLERY`ADD - Set.
```

After the next upload:

```
New picture for God: /api/wiki-assets/7ee8f545d88f41a8b4b3055adeec442c/lantern.png as gallery
```

## Reading a gallery in softcode

The gallery is kept as JSON in the character's ``PROFILE`GALLERY`` attribute, one object per image in
display order. Each object has:

- `AssetId`, `FileName`, `Url`: the stored file and its address on the site;
- `Caption` and `Warning`: text, or null;
- `Tags`: a list of words, or null;
- `Order`: its place, counting from 0;
- `IsIcon` and `IsBanner`: whether it is the avatar or the banner.
- `Official`: staff approved it as the portrait or marked it official art; left out when false;
- `PortraitPending`: its owner asked for it to be the portrait, and it waits for staff; left out when
  false;
- `Consent`: the terms the uploader accepted, as `Text`, `By` (their objid) and `At`; left out when
  the game asked for none.

Counting the images and reading the first one's caption:

```sharp
> think json_query(get(me/PROFILE`GALLERY),size)
4
> think json_query(get(me/PROFILE`GALLERY),extract,$\[0\].Caption)
At the harbour rail
```

The avatar is also copied into `IMAGE`, the banner into ``IMAGE`BANNER`` and the avatar's caption
into ``IMAGE`ALT`` every time the gallery changes, so code that only wants the avatar reads `IMAGE`.

<Aside>
Change the gallery from the portal. A value set by hand in ``PROFILE`GALLERY`` is replaced the next
time the gallery changes there.
</Aside>
