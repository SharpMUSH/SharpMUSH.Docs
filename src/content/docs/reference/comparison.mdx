SharpMUSH runs PennMUSH softcode and imports PennMUSH databases. This page lists what a PennMUSH
game gains by moving and what it gives up. For softcode that behaves differently, see
[Compatibility](/reference/compatibility/).

## What a game gains

| | PennMUSH | SharpMUSH |
|---|---|---|
| Where the world is kept | In memory, written to a flatfile on each dump | An LMDB database; each change is a transaction written as it happens |
| Backups | A copy of the last dump | `@backup` copies the live world while players stay connected |
| Configuration | `mush.cnf`, edited on the server's disk | Stored by the server, edited in the portal or with `@config` |
| Staff powers | WIZARD, ROYALTY and powers | The same, held as [roles](/reference/sharpmush-help/roles/); a game adds its own roles and permissions |
| Logins | One character per login | An account with several characters; sign-in with Discord, Google and others |
| Website | Separate, if the game runs one | Built in: terminal, mail, scenes, wiki, profiles, admin pages |
| Discord | Separate bot, if any | Channels linked to the game by the [Discord plugin](/guides/discord/) |
| Installing softcode | Paste a file | [Packages](/guides/packages/) with review, upgrade and rollback |
| Longest function result | 8,192 characters | 5 MiB (64 KiB for a guest) |
| Extending the server | Patch and rebuild the C source | Load a [C# plugin](/guides/plugins/) into a running server |

`examine` can also lay out and colour an attribute's code, when the attribute has the `cmdsyntax` or
`funsyntax` [attribute flag](/reference/sharpmush-help/attribute-flags/).

## What to weigh

- **A younger code base.** PennMUSH has decades of use behind it. SharpMUSH has a large test suite and
  a [parity harness](/guides/local-install/#comparing-with-pennmush) that replays sessions against PennMUSH, but fewer games
  have run on it.
- **The move is one way.** SharpMUSH imports a PennMUSH flatfile but does not write one. Keep the
  original game until the new one has proved itself; the
  [migration guide](/guides/pennmush-migration/) covers rehearsal and rollback.
- **Some behaviour differs on purpose.** Where PennMUSH's behaviour was a defect or clashed with a
  SharpMUSH feature, SharpMUSH chose differently. Every case is listed in
  [Compatibility](/reference/compatibility/).
- **More moving parts.** A game runs as three services (the game server, the connection server and
  the renderer) and a NATS message broker. The [Docker setup](/guides/docker-quickstart/) runs them
  together on one small server.
