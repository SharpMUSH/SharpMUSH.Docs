## Playing

### One world, three ways in

Players connect with a MU\* client over telnet, play in the browser from the game's website, or
speak from a linked Discord channel. Telnet clients get full negotiation, Unicode, and MXP or Pueblo
links and pictures where they support them. MUD clients such as Mudlet get a map, gauges and chat
windows over GMCP with the [gmcp package](/guides/mud-clients/).

A browser that loses its connection, such as a phone moving from Wi-Fi to mobile data, picks up its
session again and is sent what it missed, within a window of 24 hours by default. See
[Connections During Updates](/technical/connections/).

### Accounts and characters

A login is an **account**, and an account holds several characters. A player switches character
without reconnecting, and can sign in with
[Discord, Google and other services](/guides/sign-in-services/). In a telnet client, `register` and
`login` reach the account, `create` and `play` create and connect its characters, and `claim` adds
a character the player already has.

### The web portal

Every server serves a [web portal](/guides/web-portal/) from the same address as the game: a Play
terminal, mail, scene logs, the wiki, character profiles and galleries, and the staff's admin pages.
It works on a phone and with [screen readers](/guides/screen-readers/), and each player can choose a
[theme](/guides/portal-themes/). The [command palette](/guides/command-palette/) runs a game command
from any page.

### Roleplay tools

The systems a roleplay game expects are [packages](/guides/package-library/), installed from the
portal: [scene logging](/guides/scenes/) that streams to the portal as it is posed, scheduling,
[safety tools](/guides/scene-safety/), [character applications](/guides/character-applications/),
[finger profiles](/guides/finger/), [jobs](/guides/jobs/), [bulletin boards](/guides/bboards/),
[a character roster](/guides/roster/) and more.

## Running a game

### Roles instead of a wizard bit

Staff powers are **roles**, held by characters, objects and accounts. WIZARD and ROYALTY are the
`wizard` and `royalty` roles, and each PennMUSH power is a permission a role can allow. A game makes
its own roles with `@role` or on the portal's Roles page, each allowing or denying permissions, and
orders them so that a role manages only those below it. See
[roles](/reference/sharpmush-help/roles/) and [security](/reference/sharpmush-help/security/).

### Run it from a browser

Configuration, roles, moderation, sitelock, backups, packages and database imports all have pages in
the portal. Settings are stored by the server and edited from the portal or with `@config`; there is
no `mush.cnf` to keep in step. See [The Web Portal](/guides/web-portal/#the-admin-panel).

### Backups while the game runs

The world is an **LMDB** database inside the server process: one directory on disk and no separate
database server. `@backup` writes a consistent copy of the live world while players stay connected,
and can run on a schedule. [Object snapshots](/reference/sharpmush-help/snapshots/) recover a single
room or code object without restoring the whole world. See the
[Operator Handbook](/guides/operator-handbook/).

### Hosting

A game runs from one Docker Compose file, and a [one-click installer](/guides/one-click-hosting/)
sets one up on a rented server. The connection server holds players' connections while the game
server is updated, so most updates disconnect no one.

### Bring your world

The portal [imports](/guides/pennmush-migration/) a PennMUSH, TinyMUX or RhostMUSH database with its
mail and configuration. TinyMUX and RhostMUSH softcode is rewritten where it can be, and every
rewrite is listed for review. SharpMUSH runs PennMUSH softcode, and the
[Compatibility](/reference/compatibility/) pages list where it differs.

### Discord

The [Discord plugin](/guides/discord/) links Discord channels to the game. Lines said in the game
are posted in the channel, and a linked member's message comes back in as the character they chose.
Game roles can give Discord roles, a game ban can ban on Discord, and scheduled scenes can appear in
Discord's Events tab.

## Building the game's systems

### Softcode

SharpMUSH runs PennMUSH softcode and adds to it: every command has an output the next command reads
as `%>`, functions take [named arguments](/guides/named-arguments/), and Markdown renders for every
client. Each command runs under a time budget, so a runaway loop cannot
stall the game. See [Your first softcode command](/guides/your-first-softcode-command/).

### Displays that adapt to the reader

[Layout functions](/guides/visual-layouts/) describe a display as boxes, tables, columns, gauges and
figures, not as a grid of spaces. The same display is drawn as Unicode art in a terminal, ASCII for a
client without UTF-8, HTML in the portal, and plain reading order for a screen reader.
[Layout themes](/guides/layout-themes/) give a game one look, and players can pick their own.

### Packages

Softcode is installed as [packages](/guides/packages/): YAML that declares the objects, attributes,
flags and locks that should exist. The server shows what an install or upgrade will change before it
writes anything. Upgrades keep local edits, and every change can be rolled back. The
[package library](/guides/package-library/) holds the systems listed above.

### Portal pages from softcode

[Portal applications](/guides/applications/) are pages and forms that softcode describes and the
portal draws, such as a character generator or a request form. They need no change to the portal
itself. Staff lay out a page's sections in the portal's App Builder.

### The wiki and its facts

The portal's wiki holds the game's setting and rules. A page can state [facts](/guides/wiki-facts/),
such as a spell's level, that the portal and softcode can search.

### Events and HTTP

Softcode answers [events](/guides/events/) in the world and [HTTP requests](/reference/sharpmush-help/http/)
to `/http/<path>`. A new game has a handler object for each, so both work without setup.

### Editor support and analysis

The [language server](/guides/editor-support/) checks softcode as you type in VS Code, Neovim or
Emacs, and the portal's softcode editor uses the same analysis. An optional
[MCP endpoint](/guides/mcp/) lets AI tools check softcode against the game's real parser.

<Aside type="caution">
The MCP endpoint uses HTTP Basic authentication, which sends the password with every request. Only
expose it over TLS.
</Aside>

## Extending the server

### C# plugins

[Plugins](/guides/plugins/) are compiled assemblies that add commands, functions, services and hooks
without forking the server. A plugin that adds only commands, functions and hooks can be turned off
while the game runs.

### Apps that act for a player

A tool outside the game, such as a character sheet site, can [act as a character](/guides/connected-apps/)
with only the permissions its player allowed, and without the player's password.
