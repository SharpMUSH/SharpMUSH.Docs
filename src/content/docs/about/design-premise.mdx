## Softcode is the source of truth

On a MUSH, staff and players shape the game in softcode, from inside it, without access to the
server's files. SharpMUSH keeps that. The engine provides general mechanisms: objects, attributes,
locks, events, HTTP routes, feeds, roles. The game's systems are written on top of them in softcode:
scenes, jobs, bulletin boards, character applications, sheets, the profile page.

So most of what a player sees can be changed by the game's own staff. A system that does not suit a
game is edited or replaced in softcode, not patched in C#.

## Systems ship as packages

Pasting a `.mush` file into a game works, but it cannot be upgraded or taken back out. SharpMUSH
installs softcode as [packages](/guides/packages/): the server works out what an install or upgrade
will change, staff review it, and only then is it written. Local edits survive an upgrade, and every
change can be rolled back. The systems that come with SharpMUSH are packages too, and a game can
remove any of them.

## One world, played from anywhere

The same world is reached from a MU\* client, the game's website and Discord. A command typed in the
browser runs exactly as one typed over telnet. Output is described once and drawn for each reader: a
table becomes box art in a terminal, ASCII for a client without UTF-8, an HTML table in the portal and
plain reading order for a screen reader.

## Staff run the game from a browser

Configuration, roles, moderation, backups, packages and imports all have pages in the portal. Settings
are stored by the server, not in a file, and in-game commands such as `@config` edit the same
settings.

## Bring your world

Many games have years of code and history. SharpMUSH runs PennMUSH softcode, imports PennMUSH,
TinyMUX and RhostMUSH databases, rewrites the TinyMUX and RhostMUSH code it can, and lists what it
could not. Where SharpMUSH behaves differently from PennMUSH, the
[Compatibility](/reference/compatibility/) pages say how and why.

## Extend without forking

When softcode is not enough, a [C# plugin](/guides/plugins/) adds commands, functions and services to
a running server. The Discord bridge, the world map and the scene system are plugins themselves.

## Who it is for

SharpMUSH suits a game that wants the depth of MUSH softcode with a website, accounts and Discord
around it: an existing PennMUSH, TinyMUX or RhostMUSH game moving to a newer server, or a new game
whose staff are willing to write or install softcode.

## Other servers

- [PennMUSH](https://www.pennmush.org/), [TinyMUX](https://github.com/brazilofmux/tinymux) and
  [RhostMUSH](https://github.com/RhostMUSH/trunk) are the servers SharpMUSH's softcode comes from.
  They are actively developed. A game that wants only a telnet MUSH is well served by them.
- [AresMUSH](https://aresmush.com/) is a ready-made game with a website, scene logging and combat,
  written in Ruby. Its systems are changed in Ruby by someone with access to the server's files.
- [Evennia](https://www.evennia.com/) is a Python framework for building any kind of MU\*. A game's
  systems are Python code written by its developers.

SharpMUSH sits between them: a website and modern tools like AresMUSH, with the game's systems
written in softcode from inside the game like PennMUSH.
