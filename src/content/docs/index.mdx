## Less to look after

<CardGrid>
	<Card title="Systems as packages" icon="puzzle">
		Chargen, scenes, boards and jobs come as [packages](/guides/packages/). Installing one takes
		seconds from the admin pages, with no install script to paste into the game. See what it will
		change first, and roll it back if you change your mind.
	</Card>
	<Card title="Backups while people play" icon="document">
		[Copy the live world](/guides/operator-handbook/) without stopping the game, on a schedule if
		you like.
	</Card>
	<Card title="Updates keep players connected" icon="rocket">
		Restarting the game server for an update [doesn't drop anyone](/technical/connections/).
	</Card>
	<Card title="Roles, not one wizard bit" icon="setting">
		Give a staffer the jobs queue or the wiki without giving them the whole game. See
		[roles](/reference/sharpmush-help/roles/).
	</Card>
</CardGrid>

## What stays the same

Players and coders carry on as they are.

<CardGrid>
	<Card title="Commands and softcode" icon="pencil">
		SharpMUSH runs PennMUSH commands and softcode, and coders can write it from their client as
		before. The [differences](/reference/compatibility/) are listed.
	</Card>
	<Card title="Clients" icon="laptop">
		Any MU\* client connects over telnet, with MXP, Pueblo and [GMCP](/guides/mud-clients/) for the
		clients that use them.
	</Card>
	<Card title="Bring your game" icon="random">
		[Import](/guides/pennmush-migration/) a PennMUSH, TinyMUX or RhostMUSH database with its mail.
		Code from TinyMUX and RhostMUSH is rewritten where it can be, and the import lists every change
		for you to check.
	</Card>
</CardGrid>

## Easier to build with

<CardGrid>
	<Card title="Character profiles from your own sheets" icon="information">
		The website's character list and profile pages are answered by softcode on the game's HTTP
		handler, so they show your game's own sheet, fields and groups. `json_fill()` fills a JSON
		template kept in an attribute, and [named arguments](/guides/named-arguments/) (`%<name>`) and
		`chain()` keep that code short.
	</Card>
	<Card title="Forms written in softcode" icon="list-format">
		Chargen, applications and staff requests can be [forms on the website](/guides/applications/),
		written in softcode the way a `+command` is, or put together in the portal's App Builder.
		[`@http`](/guides/web-requests/) lets the same code call outside web services.
	</Card>
	<Card title="Layouts in the game's look" icon="seti:html">
		`box()`, `fields()`, `datatable()` and `gauge()` describe a display once. Each player sees it
		drawn in the game's [layout theme](/guides/layout-themes/) at their own screen width, and a
		screen reader reads it in order. See [visual layouts](/guides/visual-layouts/).
	</Card>
	<Card title="Plugins for the rest" icon="seti:c-sharp">
		When softcode isn't enough, a [C# plugin](/guides/plugins/) adds commands, functions and
		services to the server, without a fork.
	</Card>
</CardGrid>

## Players get a better game too

Their own client or a browser, on a computer or a phone. [Scenes](/guides/scenes/) logged as they
pose. One account for all their characters. [Screen-reader](/guides/screen-readers/) support in
both.
